图中知识点 · 条件记忆

Engram 是什么？

查什么？以当前位置结尾的连续 token 组合，称为 N-gram。V4.1 使用 2、3、4-gram。

查到什么？训练学到的向量。它们存在模型的记忆表里，随模型一起训练。

怎么用？将查出的向量投影为 Key 和 Value；当前隐藏状态与 Key 计算门控，再用门控调节 Value，补入主干。

什么时候用？V4.1 在从 0 开始计数的第 1、14 层放置 Engram，均位于 Encoder。Prefill 和逐 token 的 Decode 都会经过这些层。

这里的记忆属于模型参数；当前会话中保存历史注意力信息的是 KV Cache。

依据 Engram 论文 Figure 1、§2 重绘；按 V4.1-Flash §2.4.2 展示 2/3/4-gram、每种 8 个哈希头，并移除原版短卷积。保留英文模块名，解释文字为中文，数学符号由 LaTeX 生成。

① 从连续 token 得到查表地址。图中假设正在处理 Great；2-gram 取 the / Great，3-gram 再带上 Alexander，4-gram 再带上 Only。这里只用英文单词示意 token，真实分词可能将一个单词拆开。Tokenizer Compression 先将等价词形等映射到规范化 ID，再构造这些组合。

每种 N-gram 经过 8 个哈希头得到各自的表地址，取出向量，再将所有结果 Concat。图中的叠片概括同一阶的多头查表。哈希地址由 token ID 决定，因此可以提前计算；记忆表里的向量由训练学习。

② 查到了，还要看当前上下文是否适合。拼接后的记忆 分别投影为 Key 与 Value。隐藏状态 与 Key 计算匹配程度，再通过 Sigmoid 得到门控 ，用它缩放 Value。门控较小，这条记忆影响较弱；较大，注入更多。

③ 将门控后的向量加回主干。左图 Engram 上方的加号表示残差相加，之后继续 Attention 和 MoE。右图只展开 mHC 的一个残差分支；实际各分支共享查表结果与 Value，并分别计算 Key 和门控。

这里 是 token 位置， 是残差分支编号， 是 Value 向量， 是该分支的门控强度， 是补入该分支的记忆增量。这是为读图采用的简化记号。

为什么要这样做？经常出现的局部组合可以从参数表中快速取出表示，让主干将更多计算用于需要结合上下文的处理。上下文门控负责判断查出的记忆在当前位置是否有用。

图中只展开一处 Engram 的结构；每层的参数与记忆表按模型配置设置。V4.1 删除了早期 Engram 图中门控之后的短卷积，因此这张图直接把门控后的记忆送回残差。
