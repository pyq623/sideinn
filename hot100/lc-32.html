第 90 题 最长有效括号

LeetCode 32 Longest Valid Parentheses

难度 困难 标签 动态规划 栈 字符串 原题链接

题面

给你一个只包含 '(' 和 ')' 的字符串，找出最长有效（格式正确且连续）括号 子串 的长度。

左右括号匹配，即每个左括号都有对应的右括号将其闭合的字符串是格式正确的，比如 "(()())"。

示例 1：

输入： s = "(()"
输出： 2
解释： 最长有效括号子串是 "()"

示例 2：

输入： s = ")()())"
输出： 4
解释： 最长有效括号子串是 "()()"

示例 3：

输入： s = ""
输出： 0

提示：

  • 0 <= s.length <= 3 * 104
  • s[i] 为 '(' 或 ')'

思路

dp[i] = 以 s[i] 结尾的最长有效括号长度。

关键观察：

  • s[i] == '('：左括号不可能是有效括号的结尾 → dp[i] = 0
  • s[i] == ')'：看能不能找到左括号和它配对

情况 1 s i 1 ' ' 到 直接配对 "... "

dp[i] = dp[i-2] + 2

前面已有的有效长度 + 这对括号本身。

情况 2 s i 1 ' ' 到 前一个也是右括号 "... "

需要跳过 dp[i-1] 长度的已匹配部分，看再前面那个字符是不是 (：

j = i - dp[i-1] - 1   ← 跳过里面已匹配的部分
如果 s[j] == '('：
    dp[i] = dp[i-1] + 2 + dp[j-1]

三段拼接：

s = ( ) ( ( ) )
    0 1 2 3 4 5
    ─── ─ ─── ─
     ③  ②  ①  ②

① dp[i-1] = 2    → 里面已匹配的部分 "()"
② + 2             → 外层这对括号 s[j] 和 s[i] 配对
③ dp[j-1] = 2    → 左边紧挨着的有效括号 "()"

dp[5] = 2 + 2 + 2 = 6

如果 dp[i-1] == 0（前面的 ) 没匹配上），说明没有已匹配的部分可跳，直接跳过。

返回值为什么是 max dp

和最长递增子序列一样——dp[i] 表示"以 i 结尾"，最长的不一定在末尾。比如 s = "()()" 后面再加个 (，末尾的 dp 就是 0。

代码实现

class Solution:
    def longestValidParentheses(self, s: str) -> int:
        n = len(s)
        if n == 0:
            return 0
        dp = [0] * (n + 1)

        for i in range(1, n):
            if s[i] == ')':
                if s[i-1] == '(':
                    dp[i] = (dp[i-2] if i-2 >= 0 else 0) + 2
                elif dp[i-1] > 0:
                    # 不大于0，说明虽然s[i-1] == ')'但前面根本没匹配上
                    j = i - dp[i-1] - 1
                    if j>=0 and s[j] == '(':
                        # 成功对应上了
                        dp[i] = dp[i-1] + 2 + (dp[j-1] if j-1>=0 else 0)
        # 末尾不一定是最大的，也许是（，那就是0
        return max(dp)
  • 易错点：
  1. 运算符优先级：`(dp[i-2] if i-2 >= 0 else 0) + 2`：必须加括号。不加的话 Python 解析成 dp[i-2] if ... else (0+2)，逻辑完全错误
  2. 条件判断的是下标合法性，不是值：if i-2 >= 0 和 if j-1 >= 0。如果写 if dp[i-2] 或 if j-1，当值恰好为 0 时会误判为 False
  3. `elif dp[i-1] > 0` 不能省：dp[i-1]=0 说明前面的 ) 没有匹配上，跳过去没有意义
  4. `j >= 0` 边界检查：j = i - dp[i-1] - 1 可能是负数，不检查会负索引
  5. 返回 `max(dp)` 不是 `dp[n-1]`：最长有效括号不一定以最后一个字符结尾
  • 复杂度：时间 O(n)，空间 O(n)

栈解法 更简洁

栈里存下标（不是字符），初始压入 -1 作为"虚拟墙"。

遍历字符串：

  • 遇到 (：压入下标
  • 遇到 )：先弹出栈顶
  • 栈空了：当前 ) 没人配对，把它的下标压入作为新的墙
  • 栈没空：有效长度 = i - stack[-1]

为什么栈顶是"墙"

栈顶始终是当前有效序列的左边界的前一个位置（墙）。i - stack[-1] = 从墙之后到当前位置的长度。

那个没匹配上的 ) 就像一堵墙——它把字符串分成了左右两段，右边的有效括号长度要从它之后开始算。压入它的下标，正好让 i - stack[-1] 算出正确长度。

初始的 -1 也是同样的道理：如果字符串一开始就能匹配（比如 s = "()()"），需要一个"虚拟墙"在位置 -1，这样 i - (-1) 才能算出完整长度。

s = ")()())"
     012345

i=4, ')': pop 3, 栈没空 → 4-0=4       stack=[0]    result=4

栈解法代码

class Solution:
    def longestValidParentheses(self, s: str) -> int:
        stack = [-1]
        n = len(s)
        result = 0
        for i in range(n):
            if s[i] == '(':
                stack.append(i)
            else:
                stack.pop()
                if not stack:
                    stack.append(i)
                else:
                    result = max(result, i - stack[-1])
        return result
