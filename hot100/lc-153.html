第 67 题 寻找旋转排序数组中的最小值

LeetCode 153 Find Minimum in Rotated Sorted Array

难度 中等 标签 二分查找 数组 原题链接

题面

已知一个长度为 n 的数组，预先按照升序排列，经由 1 到 n 次 旋转 后，得到输入数组。例如，原数组 nums = [0,1,2,4,5,6,7] 在变化后可能得到：

  • 若旋转 4 次，则可以得到 [4,5,6,7,0,1,2]
  • 若旋转 7 次，则可以得到 [0,1,2,4,5,6,7]

注意，数组 [a[0], a[1], a[2], ..., a[n-1]] 旋转一次 的结果为数组 [a[n-1], a[0], a[1], a[2], ..., a[n-2]] 。

给你一个元素值 互不相同 的数组 nums ，它原来是一个升序排列的数组，并按上述情形进行了多次旋转。请你找出并返回数组中的 最小元素 。

你必须设计一个时间复杂度为 O(log n) 的算法解决此问题。

示例 1：

输入： nums = [3,4,5,1,2]
输出： 1
解释： 原数组为 [1,2,3,4,5] ，旋转 3 次得到输入数组。

示例 2：

输入： nums = [4,5,6,7,0,1,2]
输出： 0
解释： 原数组为 [0,1,2,4,5,6,7] ，旋转 4 次得到输入数组。

示例 3：

输入： nums = [11,13,15,17]
输出： 11
解释： 原数组为 [11,13,15,17] ，旋转 4 次得到输入数组。

提示：

  • n == nums.length
  • 1 <= n <= 5000
  • -5000 <= nums[i] <= 5000
  • nums 中的所有整数 互不相同
  • nums 原来是一个升序排序的数组，并进行了 1 至 n 次旋转

思路

与上一题 搜索旋转排序数组 的区别

  • 上一题找 target：找到就提前 return mid，找不到返回 -1，用 while left <= right
  • 这一题找最小值：没有提前退出的条件，不断缩小区间，直到区间只剩一个元素就是答案，用 while left < right

核心策略 拿 nums mid 和 nums right 比较

旋转数组的结构是两段升序：[升序1, 升序2]，断裂点就是最小值。

  • nums[mid] > nums[right] → mid 到 right 之间一定有断裂（从大跳到小），最小值在右边
  • nums[mid] <= nums[right] → mid 到 right 是平滑递增的，最小值在左边或就是 mid

为什么不和 nums left 比

当 nums[left] < nums[mid] 时，只能确定左边有序，但最小值可能在左端也可能在右边，无法安全收缩区间。而和 nums[right] 比可以每轮都安全缩小区间。

为什么 right mid 而不是 mid 1

因为 mid 本身可能就是最小值，不能跳过它。而 left = mid + 1 是安全的，因为 nums[mid] > nums[right] 说明 mid 肯定不是最小值。

代码实现

class Solution:
    def findMin(self, nums: List[int]) -> int:
        n = len(nums)
        left, right = 0, n - 1
        while left < right:
            mid = (left+right) // 2
            if nums[mid] <= nums[right]:
                # 右边有序，可以确定，肯定是最小值在左边
                right = mid # 不确定最小值是不是 mid
            elif nums[mid] > nums[right]:
                # 一定是右边出现了断裂，[升序1， 升序2]
                # 所以进入右边，最小值一定不是mid，所以像二分一样mid + 1
                left = mid + 1
        return nums[left]
