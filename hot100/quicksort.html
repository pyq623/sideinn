补充题 快速排序（快排）

题面

对应练习：LeetCode 912 · 排序数组 ↗。该题要求实现升序排序，不限定必须使用快排。

给定整数数组 nums，用快速排序将所有元素按升序排列，返回排序后的数组。不要直接调用 sorted() 或 sort()。本练习允许使用额外列表。

示例：[3, 2, 1, 5, 3, 4] → [1, 2, 3, 3, 4, 5]。

思路：分区，再递归排序两边

随机选一个基准值 pivot，把数组分成 small（小于）、equal（等于）、big（大于）。分别递归排好 small 和 big，再按 small → equal → big 拼接。数组长度不超过 1 时，直接返回。快速选择只递归目标所在的一边；快排递归两边。 两者可对照复习，但解决的是不同问题。

比较点快速选择：第 215 题快速排序
共同步骤随机选 pivot，分成 small（小于）、equal（等于）、big（大于）
分完以后第 K 大在 big 就递归 big；在 equal 就返回；在 small 就调整排名后递归 small递归排序 small、big；equal 中的值都相等，无需再排
返回什么一个数：第 K 大的值quick_sort(small) + equal + quick_sort(big)
是否需要 k需要；k 从 1 开始计数不需要，要排好全部元素

同一个数组，两种后续处理

取 nums = [3, 2, 1, 5, 3, 4]，这一轮选 pivot = 3。分区后的组内还没有排序：

small = [2, 1]     equal = [3, 3]     big = [5, 4]

找第 2 大：只在 big = [5, 4] 中继续找第 2 大 → 返回 4
          small 和 equal 不必排序。

做升序快排：
    quick_sort([2, 1]) → [1, 2]
    equal             → [3, 3]    （直接保留，不递归）
    quick_sort([5, 4]) → [4, 5]
    拼接结果          → [1, 2] + [3, 3] + [4, 5]
                      = [1, 2, 3, 3, 4, 5]

分区只保证 small < pivot < big；递归负责让两侧内部有序。 因此直接返回 small + equal + big 还不算完成排序。

代码：保留分区循环，递归两边

import random


def quick_sort(nums):
    if len(nums) <= 1:
        return nums[:]  # 空数组、单元素数组已经有序

    pivot = random.choice(nums)
    small, equal, big = [], [], []
    for num in nums:
        if num < pivot:
            small.append(num)
        elif num > pivot:
            big.append(num)
        else:
            equal.append(num)

    return quick_sort(small) + equal + quick_sort(big)


print(quick_sort([3, 2, 1, 5, 3, 4]))
# [1, 2, 3, 3, 4, 5]

对比第 215 题的快速选择代码：去掉 target 与判断排名的三个分支，补上长度不超过 1 的终止条件，再用最后一行排序并拼接两边。这是返回新列表的版本，不修改原数组，也不是原地快排。

Python 用法速查：choice / sample / choices 的区别 · sort 与 sorted。

为什么一个平均 O(n)，一个平均 O(n log n)？

一次分区要扫描当前数组。用分区较均衡的情况理解：快速选择只沿一条分支走，工作量约为 n + n/2 + n/4 + … = O(n)。

这里用的是等比数列求和。首项为 a1、公比为 q 时，前 k 项之和为 Sk = a1(1 − qk) / (1 − q)（q ≠ 1）。代入 a1 = n、q = 1/2，得到 Sk = 2n(1 − 2−k) < 2n，所以总工作量是 O(n)：虽然递归多轮，但每轮处理的元素越来越少，总量不到两遍原数组。

快排两边都处理，同一递归层的总工作量约为 O(n)，约有 log n 层，因此为 O(n log n)。随机选 pivot 不保证每轮恰好对半分，这是平均／期望复杂度的直观解释。

指标随机快速选择随机快速排序
平均／期望时间O(n)O(n log n)
最坏时间O(n²)O(n²)
这两种列表版的额外空间分区较均衡时峰值 O(n)；极端不均衡时，递归栈保留多层列表，最坏可达 O(n²)。不是原地算法的空间口径。

最坏情况是连续选到极端值，使待处理部分每次只减少一个元素：n + (n−1) + … + 1 = O(n²)。三路分区会一次排除全部 equal 元素，所以全相等的数组只扫描一轮，时间为 O(n)。

易错点：只分区就返回，漏了递归

本次实测错误：输入 [5, 2, 3, 1]，如果选到 pivot = 3，分区得到 small = [2, 1]、equal = [3]、big = [5]。此时直接拼接会返回 [2, 1, 3, 5]，而正确结果应为 [1, 2, 3, 5]。

# 错误：两侧内部仍可能无序
return small + equal + big

# 正确：递归排好两侧，再拼接
return quick_sort(small) + equal + quick_sort(big)

分区只保证左右两组与 pivot 的大小关系；递归才保证每组内部有序。 equal 中的值都相等，不需要递归。本次练习记录：补上两侧递归后，LeetCode 912 提交通过。

复习时抓住这几处

  • equal 不能丢： 重复值也要留在排序结果里；第 K 大同样把重复元素计入排名。
  • equal 不再递归： pivot 来自当前数组，equal 至少有一个元素，两边递归的问题规模才会缩小。
  • 升序拼 small → equal → big： 想改为降序，应在每层递归都使用 big → equal → small 的拼接顺序。
  • 原地写法是下一步： 若面试要求原地排序，要用下标和交换在原数组内分区，再递归两侧区间；不能把这里创建三个列表的代码称为原地快排。
