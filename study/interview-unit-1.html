面试单元1 · Agentic RL：从交互到参数更新

分清Agent、环境、轨迹、奖励与训练，建立完整闭环。

每节读完紧接3题，再用口述追问练表达。

1. 一次Agent任务如何变成一次训练

先记住：Agentic RL训练的是模型在与环境交互时，怎样选择更有利于完成任务的行动。 能调用工具只是运行能力；只有收集交互结果、计算训练信号并实际更新策略参数，才完成一次RL策略更新。更新是否带来能力提升，还需要独立评测。

用一个贯穿课程的教学任务说明：在隔离的代码仓库里修复CSV解析器，并由可信评测器运行隐藏测试。 这不是Accio业务原题，而是为了把概念落到具体对象。

1.1 谁在行动，谁在执行，谁在学习

对象 在例子中是什么 容易混淆的地方
Policy / actor 生成分析、补丁和工具调用的语言模型 actor是可训练策略，不等于整个Agent程序
Harness / agent loop 组装上下文、校验调用、执行工具、管理循环的程序 harness可变化，但通常不通过梯度一起训练
Environment 仓库、文件、shell、测试程序等状态及交互规则 环境不只是一个Docker镜像
Sandbox 承载执行的隔离空间及资源边界 sandbox解决“在哪执行”，不自动定义任务成功
Reward / verifier 按任务规则检查修复结果并给出评价 “模型说修好了”不能作为充分证据
Learner 根据轨迹和学习目标更新模型的训练进程 一般不必与每个工具执行器放在同一个沙箱

为什么必须区分模型与harness？ 若只给同一个模型换了更好的搜索工具，成功率也可能上涨。这说明系统更强，但不能直接归因为“RL把模型训强了”。

原例题：日志进入训练器，就算学过了吗？ A系统只记录Agent日志；B系统将日志送入训练器，但学习率为0；C系统利用经过验证的交互结果更新策略。哪个真正完成了策略学习？

解析：选C。 A只完成数据收集；B虽然运行了训练流程，但在本题设定下没有实际改变策略参数；C完成了策略更新。不过，“已更新”不等于“已变强”，还要控制harness、任务和推理预算，在独立任务上比较更新前后的表现。

1.2 把C系统展开：一条轨迹怎样变成训练样本

这里的轨迹（trajectory），是一次任务中模型所见的上下文、模型生成的动作、环境返回的观察以及结束状态等记录。训练还需要与之对应的奖励、mask、策略版本和概率信息。它不是仅有最终答案的一段文字，也不是把全部运行日志直接拼起来就能训练。

  1. 采样与交互。 从固定仓库版本启动任务。模型读文件、生成补丁、调用测试工具；harness执行请求并把观察交回模型。
  2. 验证任务结果。 任务结束后，评测器检查实际提交的文件并运行规定的隐藏测试。记录成功、失败或部分完成，也区分平台故障和预算截断。训练用隐藏测试与独立评估任务应区分，避免用训练反馈冒充泛化证据。
  3. 组装训练样本。 对齐实际生成的token、当时可见的上下文和loss mask；按算法保存或计算采样策略的log-prob等信息。奖励通常作为数值字段保存，不要求模型生成“reward=1”。
  4. 计算学习信号。 从奖励得到回报或优势。优势可以先理解成“这次表现相对比较基准好多少”，不一定等于原始奖励。
  5. 计算损失并更新。 learner在选定的模型输出位置计算策略损失，反向传播并执行优化器更新；随后用新权重继续采样。

“经过验证”指反馈有可信依据，不是“验证成功的轨迹才准训练”。 真实且可归因的失败同样能提供学习信号。隐藏测试失败和沙箱服务宕机需要分别处理，不能不加区分地都当成模型能力不足。

1.3 一条完整轨迹：哪些位置计算策略损失

以下按常见的多轮actor RL训练说明，假定保留本次采样中的分析、工具调用和最终回答。loss_mask=1表示该token纳入策略损失，0表示不纳入。表格按内容块示意；实际mask必须与token位置对齐。它不是所有训练方法通用的唯一配置。

顺序与内容 谁产生 loss mask 用途
① 系统规则、工具定义、用户任务 外部输入 0 提供任务与约束
② “先检查引号处理逻辑” 被训练策略采样 1 优化分析与规划行为
③ read_file("parser.py") 被训练策略采样 1 优化工具选择和参数
④ 解析器文件内容 工具返回 0 作为后续决策的观察
⑤ apply_patch(...)，含补丁正文 被训练策略采样 1 优化修改代码的行为
⑥ “补丁应用成功” 工具返回 0 提供执行反馈
⑦ run_tests() 被训练策略采样 1 优化测试调用
⑧ “2个测试失败”，含报错 工具返回 0 为下一次修正提供依据
⑨ 根据报错生成第二次补丁 被训练策略采样 1 优化利用反馈修正的行为
⑩ “修复已提交” 被训练策略采样 1 优化最终回应与结束行为
⑪ 任务结束后，隐藏测试给出奖励 可信评测器 不作为生成目标 计算回报、优势等信号
⑫ padding补齐位置 训练程序 0 不承载任务内容

工具调用和工具返回必须分开。 选择run_tests()、生成工具名和JSON参数，是模型的动作，通常要训练；测试打印的stdout、退出码和错误栈，是环境观察，通常不作为actor生成目标。同一段代码，从读文件工具返回时是观察，由模型写入补丁时是动作，不能仅凭文字内容判断mask。

verl的Agent Loop把模型输出和工具返回都放入response_ids，再用response_mask区分：模型生成位置为1，工具返回位置为0。初始prompt单独保存，因此上表是完整序列的教学示意，不表示prompt也必须放进verl的response_mask数组。官方接口说明

再核对来源。 人工补写的正确答案、教师模型输出、历史对话中的assistant消息和harness固定插入的文本，不能仅凭角色标签就冒充本轮策略采样。它们可以按目标作为上下文、SFT示范或蒸馏信号使用，但不能直接混入普通on-policy RL动作。分析文本若确由本次策略采样且被纳入训练，也可以计算损失；“思考过程一律mask”并不是通用规则。固定模板标记与模型实际生成的结束标记也应按来源、目标和实现约定分别处理。

1.4 mask掉损失，不等于删掉上下文

“用于训练”至少有三种含义：作为输入、作为优化目标、作为评价信号。 用户问题和工具返回主要作为输入；策略生成的token是优化目标；reward和advantage提供评价信号。只有后两类分清了，才不会把“工具返回不算策略损失”误读成“模型学不到工具反馈”。

机制 回答的问题 工具返回如何处理
loss mask 是否把这个token的输出概率纳入策略损失？ 通常为0，不要求模型复述工具结果
attention mask与因果可见性 预测当前位置时能读取哪些上下文？ 后续输出可读取先前工具反馈；不能读取未来结果

例如，工具返回“引号未闭合”，模型随后生成修正补丁。训练优化的是给定任务、先前动作和这条报错时，模型生成下一步补丁的概率。报错仍在输入里，所以模型能学习如何利用报错行动。

不要说“mask为0的部分完全没有梯度”。 准确说法是该位置没有直接的策略损失项；后续输出依赖上下文，梯度仍可能经过处理这些上下文的计算路径。loss mask也不会自动冻结某一组模型参数。

例题1：给整条轨迹标mask。 为简化，每一块只写一个值：

用户任务 → 模型读文件调用 → 工具文件内容
         → 模型补丁 → 工具报错 → 模型修正 → padding

解析： 在上述约定下，loss mask依次为[0, 1, 0, 1, 0, 1, 0]。其中，工具返回的文件内容和报错不作为预测目标，因此对应位置的loss mask为0；这些内容仍保留在上下文中，供后续模型输出使用。例如，训练修正后的工具调用时，模型需要依据此前的报错来决定如何修改参数。

1.5 mask决定参与位置，优势决定学习方向

为了看清两者分工，先使用一个简化的策略梯度损失，暂不展开PPO／GRPO的概率比、裁剪、KL项和归一化：

LPG=−∑imiAilog⁡πθ(xi∣hi)L_{\mathrm{PG}}=-\sum_i m_i A_i\log\pi_\theta(x_i\mid h_i)LPG​=−i∑​mi​Ai​logπθ​(xi​∣hi​)

这里iii表示token位置，mim_imi​是loss mask，xix_ixi​是该位置实际采样的token，hih_ihi​是生成它时可见的上下文，AiA_iAi​是训练时视为固定信号的优势。mask回答“算不算这一项”，优势回答“这一项鼓励还是抑制”。

  • mi=0m_i=0mi​=0：该位置不直接贡献这项策略损失。
  • mi=1,Ai>0m_i=1, A_i>0mi​=1,Ai​>0：这项梯度推动模型提高该输出的条件概率。
  • mi=1,Ai<0m_i=1, A_i<0mi​=1,Ai​<0：这项梯度推动模型降低该输出的条件概率。
  • mi=1,Ai=0m_i=1, A_i=0mi​=1,Ai​=0：该位置已被选中，但这项策略梯度信号为0；其他损失或优化器机制仍可能影响参数。

这些是单项梯度的方向，不保证一次共享参数更新后，每个token的概率都严格按该方向变化。数值损失为0也不自动意味着梯度为0，不能仅看loss标量判断是否发生学习。

例题2：奖励为0，就没有训练信号吗？ 采用GRPO的简化教学设定：同一任务采样4条轨迹，奖励是[1, 0, 1, 0]。优势计算只做组内中心化，不除标准差：Aj=Rj−R‾A_j=R_j-\overline RAj​=Rj​−R。求每条轨迹的优势，并判断失败轨迹是否应mask掉。

解析： 平均奖励为0.5，优势为[+0.5, -0.5, +0.5, -0.5]。在把轨迹优势广播到其可训练token的设定下，失败轨迹中的模型动作仍可保留mask=1，通过负优势提供抑制信号。若4条奖励全为0，中心化优势就全为0，这一项没有相对学习信号；不能概括成“失败样本一定有负梯度”。标准化方式和附加损失取决于算法配置。GRPO优势的官方说明

1.6 验证了结果，不代表验证了每一步

一次最终成功的轨迹，可能包含无效搜索、错误补丁和后续修正。“成功轨迹”是结果标签，不是每个动作的正确性标签。 如果把同一个正优势广播给整条轨迹的全部模型生成位置，前面的弯路也可能一起受到鼓励。这就是长程信用分配难题；第2节继续解释回报和过程反馈。

例题3：先改错、再改对，第一份补丁要mask吗？ Agent生成错误补丁，测试报错，随后修正，最终隐藏测试通过。有人建议：“把第一份补丁的mask改成0，剩下全设1，就解决了信用分配。”这个说法可靠吗？

解析：不可靠。 在只用最终结果奖励的常见GRPO设定下，通常将同一个轨迹优势广播到该轨迹的所有可训练模型输出token；错误补丁和修正补丁都保留loss mask=1。这不会自动区分各步骤的贡献；当轨迹优势为正时，前面的错误动作也可能受到鼓励。若希望不同步骤获得不同学习信号，需要额外的信用分配设计与可信依据，不能仅靠把错误补丁的mask改为0就认为问题已解决。

例题4：同一条失败日志，SFT与RL怎样使用？ 一条轨迹里，模型调用工具时把路径写错，工具返回“文件不存在”。可否把它直接作为正确示范做普通SFT？可否用于RL？

解析：不能直接作为正确示范做普通SFT；可以用于RL，但需结合奖励和优势使用。

对于SFT： 如果把错误的工具调用作为监督目标，训练就会鼓励模型重复这个错误。可以提供正确调用作为示范，或保留错误历史作为上下文，只监督后续的正确修复。

对于RL： 真实采样得到的失败动作可以参与训练，其学习方向由奖励和优势决定。以GRPO为例，若该轨迹相对同组其他轨迹表现更差、优势为负，就会提供抑制这些动作的信号；失败本身不保证优势为负。同时，需要区分模型把路径写错与平台故障，避免把环境问题误当作模型表现。

例题5：给旧轨迹补上事后反馈，再重算log-prob，合理吗？ 模型根据用户任务生成了读文件、写补丁等动作，完成一次修复任务。随后，评测器运行隐藏测试，发现补丁仍未正确处理转义引号。工程师把这条反馈追加到最初的用户提示中，保留原轨迹中的动作和工具返回不变，不让模型重新生成解题过程，只做一次forward，计算原动作各个token在新上下文下的log-prob，并直接用于这条原始轨迹的GRPO更新。这样是否合理？

原来采样时：
提示：修复 CSV 解析器。
模型动作：读取 parser.py → 写入补丁 A

重新计算时：
提示：修复 CSV 解析器。注意，你遗漏了转义引号。
保留的动作：读取 parser.py → 写入补丁 A

解析：不合理。这里是在给旧动作重新算概率，不是让模型重新做题。 原动作生成时没有看到这条反馈；修改提示后，算出的是“已知遗漏转义引号时，采取原动作的概率”，不能直接当作原始交互条件下的动作概率用于更新。问题不在于重新forward，而在于事后改变了动作当时可见的上下文。

如果任务规则允许提供这条反馈，可以让模型据此重新生成一条轨迹，或在原轨迹末尾收到反馈后继续生成修正动作，再按实际上下文训练这些新动作。评测反馈也可以用于计算原轨迹的奖励，但不应倒填进旧动作生成前的提示。

考前复述： “我先区分策略、harness、环境、验证器和learner。一条轨迹里，任务与工具观察作为上下文，策略实际生成的token按目标计算损失，可信验证结果用于计算奖励与优势。mask决定参与位置，优势决定学习方向；失败轨迹不自动排除，最终成功也不保证每步正确。最后确认参数实际更新，并在独立任务上验证收益。”

2. 状态、观察、动作与长程信用分配

长程信用分配（long-horizon credit assignment）讨论如何把延迟结果归因于此前的动作；常见的结果监督GRPO通常广播轨迹优势，不自动区分每步贡献。多轮工具调用、奖励延迟且需要区分关键动作与无效步骤时，可考虑额外设计更细的步骤级回报或优势；下文的折扣回报只是教学示例，并非所有算法的默认配置。

RL前的冷启动：先用SFT建立基础行为。 这里的冷启动（cold start）指在正式RL训练前，为模型建立基本任务行为；常见做法是用少量高质量示范做SFT，让后续探索有一个较好的起点。“冷启动”描述训练阶段与目的，SFT是具体方法：用SFT做冷启动时，仍使用前面的交叉熵损失，没有额外一种“冷启动loss”。

例如，先用正确交互示范教模型输出合法的工具JSON、读取工具结果并继续操作，再让它通过RL根据任务奖励改善行动策略。若起始模型已具备这些基础行为，也可以直接尝试RL，并非必须先做一轮SFT；模板、schema与解析器的检查则属于工程准备，应与模型训练区分。

例题。 一个模型100次任务中70次在首次工具调用就因格式错误失败。此时直接把rollout规模放大10倍，未必解决根因；优先检查模板、schema、解析器与示范覆盖，先让有效交互比例上来，再测RL收益。

如果蒸馏不可用怎么办？ 先分清是教师接入不可用，还是现有策略没有成功能力。可讨论：执行环境与测试器提供反馈、自生成候选+验证筛选、课程难度调整、领域数据补充、人工小规模示范。每项都应说明“信号从哪里来”和“怎样判断有效”，不是把框架名称换一遍。

考前复述： “SFT给示范，偏好方法给比较，蒸馏给教师监督，环境RL给自己行为的后果。它们可以组合，组合顺序取决于能力缺口和预算。”

4. 有效评测：成功率、pass@k、可靠性与归因

先定义一个任务的成功条件，再谈“效果提升”。修解析器可以要求隐藏测试通过、输出文件正确且没有修改测试器；真实业务任务还需考虑约束遵循、人工介入与成本。

pass@1关注单次尝试成功；pass@k关注 kkk次尝试中至少一次成功。在“每次独立、成功概率均为 ppp”的教学假设下：

P(至少一次成功)=1−(1−p)kP(\text{至少一次成功})=1-(1-p)^kP(至少一次成功)=1−(1−p)k

例如 p=0.5,k=3p=0.5,k=3p=0.5,k=3，至少一次成功的概率为 1−0.53=0.8751-0.5^3=0.8751−0.53=0.875。这说明增加尝试次数本身就能涨pass@k，不能直接当作模型变强。实际benchmark常用有限样本无偏估计量，且尝试并非总独立；本公式只用于概率直觉。

重复都成功是另一个指标。 同样假设下，三次都成功为 p3=0.125p^3=0.125p3=0.125，与“至少一次成功”的0.875相差很大。不要混淆pass@k与某些报告中的Pass³；后者定义应回看具体benchmark。

如何证明RL有用？ 教学设计：保留同一个起始checkpoint、harness、任务集、最大步数与推理预算，对比未训练、SFT与RL后的模型。固定训练/验证/测试划分，并按任务族、模板或仓库去重；只在验证集选超参数，最终报告独立测试集。

至少同时看：①成功率和置信区间/重复波动；②每成功任务成本、token数、时延；③任务分桶效果与长尾失败；④无效环境比例；⑤约束违例。过滤平台故障后报策略成功率可以，但还要独立报环境可用率与端到端成功率，不能把故障藏掉。

例题。 旧模型最多试1次，新模型最多试8次，新模型pass@8更高。这不能证明RL提升单次能力。先在相同预算下比较pass@1与成本曲线，再检查更多样本是否只是覆盖到已有能力。

pass@k接近pass@1之后： 可能是任务已稳定，也可能是所有尝试都在同类困难任务上失败。先看失败分桶、采样多样性与任务难度，不能仅据差距变小宣布“RL能力已到顶”。

展开精简参考答案

记忆顺序：固定条件 → 同预算比较 → 增预算对照 → 独立验证。

两种收益都可能存在，需要用对照实验区分：

  1. 固定条件： 在同一组未参与训练的测试任务上，比较RL前后的模型，保持harness、工具、评测器、采样设置和单次生成预算一致。
  2. 看参数收益： 固定采样次数，比较更新前后的pass@1和相同k下的pass@k。相同条件与预算下的稳定提升，才支持参数更新有效；不能用新模型的pass@8对比旧模型的pass@1。
  3. 看采样收益： 对每个模型分别增加采样次数，如1、2、4、8次，比较成功率与实际token、时间成本。同一模型增加预算带来的提升，体现采样收益；再比较新旧模型在相近成本下的表现。
  4. 确认可靠性： 重复评测并报告不确定性，按失败类型分析。pass@k只表示k次中至少成功一次，不能代替单次成功率或重复运行的稳定性。

结论：固定预算看参数更新，同一模型增加预算看采样收益，两者可以同时存在。
